Frontend Super Admin Application Q&A is now a three-panel workspace:

  Profile → Date (default today, America/New_York) → Session list → Q&A detail

days) are accurate at scale, and return an explicit company name when possible.

================================================================================
CHANGE 1 — Date filter on sessions list
================================================================================

GET /admin/application-qa/sessions

FE now also sends (when a day is selected):

  date=YYYY-MM-DD
  day=YYYY-MM-DD          (alias)
  timezone=America/New_York
  tz=America/New_York     (alias)

Optional range aliases (accept if easy):

  from=ISO
  to=ISO

Rules:

  - When `date` / `day` is present, return only sessions whose activity timestamp
    falls on that calendar day in `timezone` (default America/New_York).
  - Activity timestamp preference (first non-empty):
      lastSyncedAt → updatedAt → createdAt / recordedAt
  - Still honor `userId`, `q`, `page`, `limit`.
  - Sort most recent first (same activity timestamp desc).
  - Without `date`, keep previous behavior (all days for that user / search).

Until this ships, FE client-filters the page of results by Eastern day — that
breaks once a profile has more than one page of sessions across days.

================================================================================
CHANGE 2 — companyName on session payloads
================================================================================

On list + detail session objects, include when known:

  "companyName": "Scale Army Careers"

Also accept / continue returning:

  tabUrl, pageTitle, status, itemCount, updatedAt, lastSyncedAt, createdAt, owner

FE falls back to parsing pageTitle (`Role @ Company`) or hostname if
companyName is missing — but explicit companyName is preferred.

4) Detail endpoint unchanged for Q&A pairs (questionsAnswers / questions_answers).
5) Non–super-admin still 403.

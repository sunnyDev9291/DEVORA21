# Backend Cursor Prompt — Super Admin Resume Analytics & Management

Copy everything below to the backend agent/developer.

================================================================================
GOAL
================================================================================

Power the Frontend Super Admin Resume dashboard:

  /super-admin/resumes              → Analytics tab (KPIs + charts)
  /super-admin/resumes?tab=browse   → Search & manage all archived resumes

Frontend client: src/lib/super-admin-resumes-api.ts

Reuse existing resume archive storage (same records as GET /resume/archives for
each user). Do NOT duplicate resume files.

Generation method is NOT part of the product surface — do not filter, aggregate,
or return web_ui / one_click_api fields.

================================================================================
AUTH
================================================================================

All /admin/resumes* routes:

1. Require authenticated session (same as /auth/me)
2. Require role/capability: super_admin
3. 401 if anonymous, 403 if not super_admin

Do NOT trust the FE temp /super-admin console password.

================================================================================
DATA MODEL (extend existing archive table)
================================================================================

Reuse the saved-resume / archive table used by POST /resume/archive and
GET /resume/archives. Ensure these columns exist (add migrations if missing):

  id                    UUID PK
  user_id               UUID FK → users (profile)
  bid_at / created_at   timestamptz  (prefer storing UTC; analytics bucket in TZ)
  job_title             text
  company_name          text
  job_description       text
  resume_file_name      text
  pdf_file_name         text
  docx_storage_key      text
  pdf_storage_key       text
  created_at            timestamptz DEFAULT now()

Indexes (critical for admin scale):

  (bid_at DESC)
  (user_id, bid_at DESC)
  GIN / trigram or ILIKE indexes for company_name, job_title, job_description
  (optional) full-text search vector on company + title + jd + profile name

Timezone:

  - Store timestamps in UTC
  - Accept `timezone` query (IANA, e.g. America/New_York) for day/week/month buckets
  - Default timezone = UTC if omitted
  - "today" / "week" / "month" computed in that timezone
  - Week = Monday 00:00 → now (ISO week) unless product already uses Sun-start;
    document the choice and keep it stable

================================================================================
ENDPOINTS
================================================================================

--------------------------------------------------
1) GET /admin/resumes/analytics
--------------------------------------------------

Query (all optional):

  preset            today | week | month | all | custom
  from              YYYY-MM-DD (required when preset=custom)
  to                YYYY-MM-DD (required when preset=custom)
  timezone          IANA TZ string
  profileId|userId  filter to one user
  profileName       ILIKE on user name

Do NOT accept or use generationMethod / method query params.

Response 200:

{
  "timezone": "America/New_York",
  "from": "2026-10-01",
  "to": "2026-10-13",
  "preset": "month",
  "totals": {
    "today": 3,
    "week": 18,
    "month": 64,
    "allTime": 912,
    "range": 64,
    "previousRange": 51
  },
  "series": [
    {
      "date": "2026-10-01",
      "count": 4,
      "previousCount": 2
    }
  ],
  "topProfiles": [
    {
      "profileId": "…",
      "profileName": "Franco Torrez",
      "profileEmail": "franco@…",
      "count": 22,
      "today": 1,
      "week": 5,
      "month": 22,
      "allTime": 180
    }
  ]
}

Notes:

  - series: one point per day in [from, to] (fill zeros)
  - previousCount aligns by day-of-window index for overlay charts
  - topProfiles: top ~10 by `count` in the selected range
  - today/week/month/allTime in totals are always absolute (not limited by
    custom range), so KPI cards stay meaningful
  - NO byMethod. NO method fields on series.

--------------------------------------------------
2) GET /admin/resumes
--------------------------------------------------

Query:

  q                 free-text keywords (split on whitespace; AND across tokens;
                    each token matches company OR title OR jd OR profile name/email)
  company           ILIKE
  jobTitle          ILIKE
  jobDescription|jd ILIKE
  profileName       ILIKE
  profileId|userId  exact
  preset / from / to / timezone   same as analytics
  page              default 1
  limit             default 25, max 100
  sortBy            createdAt | companyName | jobTitle | profileName
  sortDir           asc | desc   (default createdAt desc)

Do NOT accept generationMethod / method.

Response 200:

{
  "items": [
    {
      "id": "…",
      "profileId": "…",
      "profileEmail": "…",
      "profileName": "Franco Torrez",
      "jobTitle": "QA Tester",
      "companyName": "Vantum",
      "jobDescription": "…full JD…",
      "createdAt": "2026-10-12T13:18:00.000Z",
      "resumeFileName": "FRANCO_….docx",
      "pdfFileName": "FRANCO_….pdf",
      "hasDocx": true,
      "hasPdf": true
    }
  ],
  "total": 912,
  "page": 1,
  "limit": 25
}

Server-side filter + sort + pagination ONLY — never return the full table.
Items must NOT include generationMethod.

--------------------------------------------------
3) GET /admin/resumes/:id/pdf
--------------------------------------------------

Super-admin download/preview of archived PDF for ANY user.

Response: application/pdf bytes
Content-Disposition: inline; filename="…"

403/401 as above; 404 if missing.

--------------------------------------------------
4) GET /admin/resumes/:id/docx
--------------------------------------------------

Same for DOCX:

Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document
Content-Disposition: attachment; filename="…"

================================================================================
ACCEPTANCE
================================================================================

[ ] Super-admin sees non-zero KPIs from real archive data
[ ] Filtering by profileId / date changes series + totals consistently
[ ] previousRange comparison works for today/week/month/custom
[ ] Search by company, title, JD keywords, profile name works with pagination
[ ] Sort columns work server-side (no method sort)
[ ] PDF preview + DOCX/PDF download work for another user’s resume
[ ] Non-admin gets 403; anonymous 401
[ ] User-scoped GET /resume/archives still only returns own rows
[ ] No generationMethod / byMethod in any admin resume response

================================================================================
OUT OF SCOPE
================================================================================

- Deleting resumes from admin UI (v1)
- Editing JD / regenerating from admin
- Mock / fake chart data
- Generation-method analytics or filters

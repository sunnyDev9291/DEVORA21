# Backend Cursor Prompt — Per–Super Admin Gateway Credentials

Copy everything below to the backend agent/developer.

================================================================================
GOAL
================================================================================

Each Super Admin sets their **own** operator gateway username + password that
unlocks the `/super-admin` UI (second gate on top of the main Devora21 login).

This replaces the old shared hardcoded credentials (`qazwsx` / `edcrfv`).

FE (already implemented):

  Client: src/lib/super-admin-gateway-api.ts
  Gate:   SuperAdminGate (setup if not configured, else login + verify)
  Hub:    SuperAdminGatewaySettingsCard (change username/password)

FE calls (cookie / dv21_ session required; caller must be super-admin):

  1) GET  /admin/gateway-credentials
  2) PUT  /admin/gateway-credentials
  3) POST /admin/gateway-credentials/verify

Until these exist, FE falls back to **browser localStorage** (per userId) so the
UI still works — remove that dependency by implementing the APIs below.

================================================================================
AUTH
================================================================================

All three endpoints:

  - Require authenticated Devora21 session (cookie or Bearer)
  - Require **super-admin** role on that session
  - Scope credentials to the **signed-in user id only**
    (never read/write another admin’s gateway credentials)

Non–super-admin → 403
Unauthenticated → 401

================================================================================
STORAGE
================================================================================

Store per user (e.g. on User / AdminProfile):

  gatewayUsername          string, unique among super-admins (recommended)
  gatewayPasswordHash      string (bcrypt/argon2 — NEVER store plaintext)
  gatewayCredentialsSetAt  datetime (optional)

Never return the password or hash in any GET response.

================================================================================
ENDPOINT 1 — Status
================================================================================

GET /admin/gateway-credentials

Success 200:

```json
{
  "configured": true,
  "username": "ops.angel"
}
```

When not set:

```json
{
  "configured": false
}
```

Aliases FE also accepts: `isConfigured`, `hasCredentials`, `operatorUsername`.

================================================================================
ENDPOINT 2 — Create / update
================================================================================

PUT /admin/gateway-credentials

Body:

```json
{
  "username": "ops.angel",
  "password": "new-secure-password",
  "currentPassword": "only-when-already-configured"
}
```

Rules:

  - username: trim; 3–64 chars; `[a-zA-Z0-9._-]+`
  - password: 8–128 chars; hash before save
  - If credentials **not** configured yet → create (currentPassword optional/ignored)
  - If credentials **already** configured → require `currentPassword` and verify
    against existing hash before updating
  - Reject duplicate `gatewayUsername` used by another user (409)
  - On success return:

```json
{
  "configured": true,
  "username": "ops.angel"
}
```

Error examples:

  - 400 validation
  - 401 current password incorrect
  - 409 username taken
  - 403 not super-admin

================================================================================
ENDPOINT 3 — Verify (unlock console)
================================================================================

POST /admin/gateway-credentials/verify

Body:

```json
{
  "username": "ops.angel",
  "password": "…"
}
```

Rules:

  - Load credentials for **session user id**
  - Compare username (exact) + password hash
  - Success 200: `{ "ok": true }`
  - Failure 401: `{ "error": "Invalid username or password." }`
  - If not configured → 400 `{ "error": "Gateway credentials are not set." }`

Do **not** issue a new session token here. FE only uses this to unlock the UI
gate; Devora21 auth + super-admin role still gate `/admin/*` APIs.

Optional hardening (nice to have):

  - Rate-limit verify per user / IP
  - Audit log failed attempts

================================================================================
MIGRATION / CLEANUP
================================================================================

- Delete any shared env like SUPER_ADMIN_TEMP_USER / PASS if present
- Do not accept the old global qazwsx/edcrfv pair anymore
- Existing Super Admins with no gateway credentials see FE first-time setup

================================================================================
ACCEPTANCE CHECKS
================================================================================

1) Super Admin A sets username/password via PUT → GET shows configured + username
2) POST verify with correct pair → 200; wrong password → 401
3) Super Admin B cannot verify with A’s credentials while logged in as B
4) Changing credentials requires currentPassword; wrong current → 401
5) Non–super-admin → 403 on all three endpoints
6) Password never appears in GET responses or logs

================================================================================
OUT OF SCOPE
================================================================================

- Do not replace Devora21 login
- Do not change other /admin/* profile or resume APIs
- FE session unlock flag stays client-side (sessionStorage); backend only stores
  and verifies the personal gateway credentials
)
